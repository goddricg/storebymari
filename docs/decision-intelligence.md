# Supreme Decision Intelligence

The Decision Engine converts multidisciplinary analysis into an accountable action. It does not expose private chain-of-thought; it records concise arguments, evidence, assumptions, trade-offs, and falsifiers.

## Supreme Core Brain

```text
                         Supreme Core Brain
                                  │
          ┌───────────────────────┼───────────────────────┐
          │                       │                       │
   Thinking Engine        Knowledge Engine        Decision Engine
          │                       │                       │
          └───────────────────────┼───────────────────────┘
                                  │
                    Multi-Disciplinary Councils
                                  │
                       Mew Orchestrator
                                  │
                 Authorized execution and evidence
```

The Orchestrator frames the user's goal, selects the smallest useful Engines
and Councils, sequences work, resolves conflict, detects missing perspectives,
and decides whether evidence is sufficient to stop. No Engine or Council may
bypass the outcome contract, instruction hierarchy, ownership ledger, or
permission gates.

## Intelligence lifecycle

```text
Brain → Expert → Reasoning → Memory → Learning → Decision → Self Improvement
```

Interpret this as a controlled lifecycle:

1. **Brain:** frame the current problem through the three Engines.
2. **Expert:** route bounded work to relevant Dev AI roles or Councils.
3. **Reasoning:** compare claims, mechanisms, evidence, and falsifiers.
4. **Memory:** retrieve only authorized, scoped, sourced records.
5. **Learning:** update the current task from observed results.
6. **Decision:** choose an owned action under constraints and uncertainty.
7. **Self Improvement:** propose and evaluate a versioned framework change;
   never rewrite policy, memory, or permissions autonomously.

## Reasoning portfolio

Select methods instead of using all of them:

| Method | Best use | Failure to avoid |
|---|---|---|
| First principles | Mechanisms and hard constraints | Ignoring accumulated domain knowledge |
| Critical thinking | Claims, sources, logic | Reflexive skepticism without action |
| Second-order thinking | Downstream and delayed effects | Unbounded speculation |
| Systems thinking | Feedback, dependencies, bottlenecks | Diagrams without measurable state |
| Probabilistic/Bayesian | Uncertain evidence updates | Invented precision |
| Scientific method | Testable causal claims | Experiments without controls or ethics |
| Game theory | Strategic incentives and responses | Assuming perfect rationality |
| OODA | Fast-changing operational decisions | Acting without updating orientation |
| Inversion/pre-mortem | Failure discovery | Treating every risk as equally likely |
| Occam's Razor | Prefer sufficient simplicity | Choosing simple explanations despite contrary evidence |
| Pareto principle | Focus search | Treating 80/20 as a measured law |
| Hanlon's Razor | Avoid premature motive claims | Ignoring evidence of abuse |

## Debate Engine

Use independent proposals, cross-examination, falsification, synthesis, and red-team review. Blind the first round to reduce anchoring. Debate claims and mechanisms, not personas.

The facilitator maintains:

- decision contract;
- option and argument map;
- evidence and source ledger;
- assumption and uncertainty ledger;
- hard-gate and permission ledger;
- dissent and invalidation conditions;
- stopping rule.

## Decision Engine

Choose a method proportionate to the decision:

- eliminate options that violate hard constraints;
- use dominance for clearly superior options;
- use weighted criteria for multi-attribute trade-offs;
- use expected value or regret for quantified uncertainty;
- use staged experiments and real options when learning is valuable;
- use explicit risk acceptance when no option removes material risk.

Do not average incompatible judgments into a meaningless score. Preserve non-negotiable security, rights, compatibility, and permission constraints outside weighted scoring.

## Decision quality gate

A decision is ready when:

- the question and decision owner are explicit;
- material options and the status quo were considered;
- decisive claims have current evidence or labeled uncertainty;
- affected councils and stakeholders were represented;
- the strongest counterargument was addressed;
- execution, validation, rollback, and review triggers are owned;
- additional analysis has lower expected value than acting or testing.
